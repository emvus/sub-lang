# Sublang IR examples

## Choose the right example family

- **Executable serialized inputs:** [examples/wire](../wire/readme.md), consumed by the standalone compiler.
- **Executable builder:** [root-tree.ems](../programs/root-tree.ems), consumed through the capped builder launcher.
- **Readable core dumps:** the seven numbered .sublang files here, generated by SublangExamples.ems.
- **Architecture proposals:** [extended-ir.md](extended-ir.md) and [v0.4](v0.4/readme.md), illustrative rather than parser inputs.

Read the [IR developer guide](../../docs/Sublang_IR_Guide.md) for actual usage and complete builders, and [roadmap](../../docs/Roadmap.md) for open features.

There is no textual parser for .sublang/.sublang-ir. The current file interface is .sublang-wire. The builder API is written in Emerald but constructs neutral IR without an Emerald AST.

## Reading a dump

```text
v3:Int = int.add v1@value, v2@value overflow=trap failure=example.integer_failure span=1
```

v3 is a function-local SSA value defined once. Int is signed i64, Float is f64. Passing modes include value, borrow_read, borrow_write, init and owned. Span refers to source/synthetic origin. Failure names refer to explicit module failure records.

branch supplies arguments to destination block parameters. cond_branch operands are condition, true arguments and false arguments; trueArgs counts true arguments excluding the condition. Backedges supply new loop values. SSA values are not implicitly mutable.

record.with returns a new value; it does not mutate the original. Class instances use Ref and explicit initialization/mutation. Method association plus an explicit receiver does not imply virtual dispatch.

A scope marker alone proves neither lifetime nor nonescape. The generic verifier's effects/memory statuses remain distinct from additional native gate checks. Frontend noescape labels are not interprocedural proof.

## Regeneration and historical verification

The generator is [SublangExamples.ems](../../src/SublangExamples.ems). The existing examples sandbox builds it once with 6,000,000,000-byte RAM/RAM+swap limits, no extra swap/network, readonly inputs and temporary build files:

```bash
bash scripts/sublang-examples-sandbox.sh
```

Generated dumps should be regenerated after builder/schema changes. They are documentation output, not an additional full golden test suite. Native examples/results have their own bundled runner.

## Architecture v0.4

[IR Contracts](../../docs/Sublang_IR_Contracts.md) requires effect provenance, alias/location contracts, separate validation dimensions, exception CFGs, process/API boundaries and Dynamic AOT. [Extended examples](extended-ir.md) illustrate these contracts with plans and Explain/protocol reports.

The v0.4 examples contain proposed operation names/attributes and expected analysis reports. They do not claim those capabilities are implemented by the current parser/backend. Existing native functionality and remaining gaps are documented separately.

Foreign GC integration is [archived](../../archive/gc-integration/readme.md). Active Dynamic/Explain proposals use explicit ownership.
